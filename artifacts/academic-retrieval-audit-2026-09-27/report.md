# PosterApp Academic Retrieval — Audit, Test, Optimize, Compare (2026-09-27)

Execution record for `docs/prompts/academic-retrieval-audit-prompt.md`.
Scope: `lib/services/academic-connector.ts` and its provider clients (OpenAlex, Crossref,
Semantic Scholar, arXiv, Tavily), the `/api/academic/search` route, and the ISO 690 bibliography
parser in `lib/ai/thesis-context.ts` that feeds the posudok citation audit.

Baseline = commit `fe9d93a` (the connector as shipped, harness only). Optimized = this branch.

## 1. Method

| Step | What was done | Where |
|---|---|---|
| Ground truth | Real provider responses captured on 2026-09-27 for 5 queries (English, Chinese, DOI, arXiv id, retracted paper) plus DOI look-ups; stored verbatim, compacted to the fields the parsers read. | `__fixtures__/academic/recorded.json` |
| Replay | `fetch` is replaced by a router that serves the fixtures for any provider URL and can inject faults: `hang`, HTTP `status` (+`Retry-After`), `malformed`, `empty`, `network`. Query matching is Jaccard-normalised so provider-specific query rewriting does not break replay. | `lib/services/__tests__/academic-replay-fetch.ts` |
| Golden set | 8 searches (G1–G8) with document-level relevance judgments and constraints (year window, expected identifiers, "no duplicates"), 5 citation cases (C1–C5) with expected status. | `lib/services/academic-retrieval-eval.ts` |
| Metrics | P@1, MRR, duplicate-aware nDCG@5 (an identical document earns gain once; the ideal ranking is over distinct documents), duplicate rows/rate, year leaks, constraint violations, field completeness, provider agreement, verified rate, correct classification rate, `unavailable` count. | same |
| Regression contract | 31 behavioural tests, one per finding, written red against the baseline (28 failed / 3 passed at `fe9d93a`), all green now. | `lib/services/__tests__/academic-connector-regressions.test.ts` |
| Artifacts | `ACADEMIC_WRITE_ARTIFACTS=<name> pnpm exec vitest run lib/services/__tests__/academic-retrieval-benchmark.test.ts` → `<name>.json`; `pnpm exec tsx scripts/academic-retrieval-compare.ts baseline.json optimized.json comparison.json`. The baseline artifact was generated by running the *current* harness against a detached worktree of `fe9d93a`, so both sides are scored by the same metric code. | this directory |

Sandbox note: outbound TLS to the academic APIs is blocked from the sandbox, so all numbers are
from replayed real bodies, not live traffic. Latencies in the artifacts are therefore ~0 ms and not
meaningful; timeout/abort behaviour is tested with injected hangs and shortened
`ACADEMIC_TIMEOUTS_MS`.

## 2. Findings and fixes

Severity: **P1** wrong/missing results or silent data loss · **P2** degraded quality/latency · **P3** hygiene.

| ID | Sev | Finding (baseline evidence) | Fix | Test |
|---|---|---|---|---|
| AR-01 | P1 | `normalizeTitleKey` strips everything but `[a-z0-9]`, so a Chinese/Cyrillic title without DOI became key `""` and was **dropped** from the merge map (`academic-connector.ts:175-181, 408`). (The recorded `深度学习` rows all carry DOIs, so G7 hid this; the regression test replays a DOI-less CJK row.) | `titleKey()` in `academic-identifiers.ts` is Unicode-aware (NFKC, `\p{L}\p{N}`), falls back to a `title:` key; DOI ∪ arXiv ∪ title identity. | AR-01 ×2, benchmark G7 |
| AR-02 | P1 | When the caller passed a `signal`, it *replaced* the provider timeout (`signal ?? AbortSignal.timeout(...)`), so a hung provider stalled the whole search for the caller's lifetime; arXiv ignored the caller signal entirely; Tavily had no timeout at all. | `boundedSignal(signal, provider)` in `academic-http.ts` always ANDs the per-provider timeout (`ACADEMIC_TIMEOUTS_MS`) with the caller signal; every provider uses it. | AR-02 ×3 |
| AR-03 | P1 | Semantic Scholar's canonical "Attention is All you Need" has no DOI, OpenAlex's row does → keyed by title vs. DOI → two rows for one paper (G1 duplicate). DataCite arXiv DOIs (`10.48550/arxiv.*`) never matched the arXiv id. | Multi-key identity: normalized DOI, arXiv id (also derived from DataCite DOIs), and title key with `compatibleForTitleMerge` (year within 2, authors overlap or unknown). | AR-03 ×2, benchmark G1 |
| AR-04 | P1 | DOI regex kept trailing `.`/`)`/`;` from pasted text, so `10.1038/nature14539.` (G4) returned **0 results** at baseline. | `extractDoi()` trims trailing punctuation and unbalanced parentheses; `normalizeDoi()` lower-cases for identity, `stripDoi()` keeps case for display. | AR-04, benchmark G4 |
| AR-05 | P1 | `yearFrom/yearTo` were forwarded to OpenAlex only; Semantic Scholar and Crossref results from 2014 leaked into a `from: 2024` search (G6 year leak). | S2 `year=2024-`, Crossref `from-pub-date`/`until-pub-date`, and a post-merge filter that also drops unknown-year rows while a window is active; `filteredByYear` is reported. | AR-05 ×3, benchmark G6 |
| AR-06 | P1 | Verification fallback accepted OpenAlex's **top-1 for any query** as `verified` with `confidence: "medium"` (`academic-connector.ts:551-575`): whenever OpenAlex returned anything for a fabricated citation, it was "verified" against an unrelated paper (regression test replays exactly that). | `bestTitleMatch()` gated by `titleMatchConfidence` (exact / normalized / containment + author-overlap + year sanity); anything below threshold is `not_found`. | AR-06, benchmark C5 |
| AR-07 | P1 | A Semantic Scholar 429 ended the verification as `rate_limited` even though OpenAlex/Crossref were healthy (regression test: Biamonte 2017 under the shared anonymous pool). Title-only look-ups also failed for the retracted Wakefield citation (benchmark C4 → `not_found`). | DOI look-ups run across all registries in parallel; title fallbacks cascade S2 → OpenAlex → Crossref → Tavily. `not_found` is only emitted when at least one registry actually answered; otherwise the first outage status is kept. | AR-07 ×2, AR-08, benchmark C4 |
| AR-08 | P1 | ISO 690 parser regex captured `"AUTHOR, A., AUTHOR, B. Title"` as the title and left `In: Journal…` tails, so the audit searched for author lists. | `cleanCitationTitle()` strips leading author lists / years, `In:` containers, page/volume tails; parser prefers the segment after the year. | thesis-context 12/12, AR-08 |
| AR-09 | P2 | Crossref `update-to[]` / `relation.is-retracted-by` were never used, so the retraction flag depended entirely on OpenAlex `is_retracted`; with OpenAlex down (regression test) the Wakefield 1998 paper came back unflagged, and citation verification never surfaced it (benchmark C4 issue "retraction not surfaced"). | `applyRetractionRelations()` marks the retracted DOI; merge ORs `isRetracted`; verification returns `enriched.isRetracted`. | AR-09, benchmark G8/C4 |
| AR-10 | P2 | Merge kept `"Unknown Author"` placeholders over real author lists, lost `influentialCitationCount`, ignored Crossref `is-referenced-by-count`/year, and let S2's `openAccessPdf.url === ""` override a real PDF URL. | `mergePaperRecords`: real authors win, max citations, influential kept, Crossref citations/year mapped, empty strings never override. `mergedYear` keeps the earlier credible year when the primary is > 3 years later (OpenAlex re-registered Vaswani 2017 as 2025). | AR-10 ×2 |
| AR-11 | P2 | Final ranking was a pure `citationCount` sort, so a 90 000-citation near-title paper outranked the exact-title match. | Reciprocal-rank fusion (k = 60) with provider weights (OpenAlex 1.0, S2 1.0, arXiv 0.9, Crossref 0.8, Tavily 0.5), exact-title +0.05 / near-title +0.02, `0.004·log10(1+cites)` prior, `+0.01` per extra provider; all in `RANKING_TUNABLES`. | AR-11, benchmark G1/G2/G6 |
| AR-12 | P2 | Crossref used plain `query=` (returns book chapters / SSRN noise before the canonical paper) and downloaded full items. | `query.bibliographic=` + `select=` field list. | AR-12 |
| AR-14 | P3 | OpenAlex `primary_location.source` is frequently `null` while `raw_source_name` is set → venue missing. | Parser falls back to `raw_source_name`; venue completeness 0.82 → 0.96. | benchmark completeness |

## 4. Residuals and recommendations

- **OpenAlex re-registration DOI.** OpenAlex's row for "Attention Is All You Need" is the 2025
  re-post with DOI `10.65215/2q58a426`; S2's canonical record has no DOI. The merged row keeps the
  earlier year (2017) but carries that DOI. A curated "canonical DOI" override or preferring
  Crossref's DOI when years disagree would remove it; not done because it needs a policy decision.
- **ISO 690 parser, short titles.** For `LECUN, Y. et al. Deep learning. Nature 521, 436–444 (2015)`
  the regex still prefers the longer sentence ("Nature 521…") because the real title is only two
  words; the DOI path compensates in practice. A grammar-based parser is the real fix.
- **providerAgreement ≈ 0.5** is dominated by Semantic Scholar's recency bias (its top-5 for
  "quantum machine learning" is all 2025); RRF already discounts single-provider rows.
- **Latency** could not be measured against live APIs from this sandbox. Expected effect of the
  changes: worst-case search bounded by the slowest provider timeout (10 s) instead of the caller's
  lifetime; S2 back-off bounded at 5 s per attempt instead of `Retry-After` (120 s observed).
- **UI domain chips** (`components/academic-search-dialog.tsx`) prepend words such as
  `computer science machine learning` to the query, which hurts exact-title queries; the server
  `domain` field is accepted but unused. Consider mapping chips to OpenAlex `concepts`/`topics`
  filters instead (out of scope here).
- Pre-existing repo-wide `tsc` errors (210, Prisma/implicit-any in unrelated modules) are untouched;
  zero errors in the audited scope.
