# PosterApp Audit Memo — 2026-09-17

Scope: read-only deep audit of the LaTeX production loop, thesis-review pipeline,
science auto-research surfaces, app shell, and data/perf layer, followed by the
shipped improvements listed at the bottom. Complements the existing
`docs/audit/{latex,ai,product-ux}-audit-2026-09.md` memos, which cover deeper
single-domain histories.

## Strengths (keep — these are the moat)

1. **Security posture of the LaTeX loop is genuinely good.** `hasUnsafeLatex`
   blocks TeX primitives + caret-notation escapes, `parser.ts` placeholders math
   /citations/links *before* escaping and re-validates math content against a
   dangerous-command set, the compiler runs sandboxed (`compiler-runner.ts`)
   with `-shell-restricted`, remote figures are materialized locally, and the
   compile route is workspace-editor-gated, rate-limited, revision-checked and
   mutex-guarded for atomic PDF install.
2. **The markdown→LaTeX contract is documented in both code and the autofix
   prompt** (`autofix-compile/route.ts` instructs the model that content is
   Markdown and `_ % & #` are auto-escaped). Card validation names concrete
   reductions (`suggestReductions`) derived from the same height model that
   produced the overflow warning — diagnosis and advice can't contradict.
3. **Thesis review is evidence-first**: pgvector RAG with epistemic badges,
   rubric engine + templates, opponent/supervisor calibration, signoff,
   citation audit with ISO 690 issue codes, and a DOCX export path.
4. **Academic search already dedupes across providers** (normalized title +
   DOI merge in `academic-connector.ts`) and sorts by citation count.
5. **UI foundations exist and are consistently used**: semantic tokens,
   `EmptyState`, `Skeleton`, `useCopyFeedback`, Sonner wrapper, focus-trap
   hook, command palette, `lint-a11y` script.

## Shipped in this session (commits)

1. **LaTeX Error Lens v1** — `lib/latex/log-parser.ts`: structured
   `parseCompileLog()` (errors/warnings/overfull boxes with `l.NNN` line
   extraction, package errors, missing files) + `attributeIssuesToCards()`
   heuristic; `pdf-sidebar` CompileLog now renders a triage list with counts,
   severity icons and jump-to-card; raw log still available.
2. **Quick Fixes v2** — `lib/latex/quick-fixes.ts`: deterministic content
   repairs (unclosed `$`, unbalanced braces, unknown control sequence inside
   math, dangling `\ref` labels) surfaced in CardInspector Validation tab with
   one-click Apply; live **height budget meter** in the Content tab
   (soft 85% / hard 100% thresholds, token colors).
3. **Defense Readiness & Pack** — `lib/thesis-review/defense-pack.ts`: risk
   scoring (difficulty × category × evidence), readiness summary, Markdown
   Defense Pack builder; DefensePrepPanel gains risk badges, sort-by-risk,
   Copy Defense Pack, and a rehearsal timer.
4. **Search credibility pill** — `lib/services/search-quality.ts`:
   `credibilityAssessment()` (citations/OA/recency/retraction) + retraction
   flag mapped from OpenAlex; pill + retracted badge in academic search dialog.
5. **Token & polish sweep** — malformed `/100/10` opacity chains fixed;
   `amber-500`→`warning`, `emerald-500`→`success`, `blue-500`→`status-info`
   in touched/high-traffic components; `ux-polish.test.ts` locks it in.

## Playwright verification (same session)

`tests/error-lens.spec.ts` drives the real editor UI against the in-memory
demo workspace, stubbing only the HTTP boundary (`page.route`) — no database,
LaTeX compiler or academic APIs required, so it runs in CI and locally alike:

1. failed compile → structured triage list (counts, `l.NNN` badge) and
   jump-to-card attribution opens the implicated card in the inspector;
2. raw log stays available behind the toggle (`data-testid="compile-raw-log"`);
3. quick fix "Close unclosed $…$" applied from the Validation tab is
   reflected in the Content textarea;
4. height meter shows live usage and flags the overflow (`aria-valuenow` > 100);
5. academic results show the credibility pill and a hard RETRACTED badge.

Result: **5 passed** (Playwright 1.61, Chromium). Notes for future sessions:

- The editor shell needs a viewport ≥ ~1296px (side panels + top-bar actions
  mount above the `xl` breakpoint); the spec pins 1680×1000 explicitly.
- With an empty workspace list the shell opens its onboarding dialog; the
  spec dismisses it to reach the demo workspace.
- **Known defect found by the e2e run (not fixed here):** after a failed
  compile the log is auto-appended to the assistant chat; when `/api/chat`
  errors (offline provider), the Agent Panel crashes with
  `Cannot read properties of undefined (reading 'replace')` while rendering
  the failure. Needs an error-boundary / safe render fix in the chat message
  path.
