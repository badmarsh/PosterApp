# PosterApp Empirical Evaluation Methodology

**Created:** 2026-09-19 · **Branch:** `arena/01a0b84f-posterapp` (from `8fefe6a` on `main`)
**Status:** Forensic baseline (§1–§3) complete; corpus & real-benchmark build (§5) in progress.

This document is the audit trail for replacing PosterApp's simulated benchmark
numbers with real, reproducible measurements. It records, file by file, what is
**REAL** (executes real code against real data) and what is **SIMULATED**
(hardcoded, or generated by a probability model), what infrastructure can
actually support a real evaluation today, and the plan for getting there.

Ground rules (non-negotiable, enforced from here on):

1. **No fabricated numbers.** Every metric in a report, table, or docstring must
   trace to a stored raw artifact (JSON/CSV) plus a `pnpm` command that
   regenerates it.
2. **Simulation must be labelled.** Any synthetic/in-silico component lives in a
   `simulate`/`synthetic`-named file or function, is excluded from "empirical"/
   "SOTA" claims, and is flagged in its output JSON via a `methodology` field.
3. **A worse real number beats a better fake one.** If the real experiment is
   worse than the simulated one, the real one is reported.
4. **No silent skips.** What cannot be measured with current infrastructure is
   stated, with the smallest real experiment that would measure it.

### 1.1 The pipeline that produced the published numbers

Tracing how `artifacts/eval/summary.json` (Recall@10 = 0.976, "latencyP95Ms": 41,
`recallAdvantageOverNaiveRagPct: 480`) was produced:

```
getGradedGoldenSet()                104 keyword-tagged queries (no corpus binding)
        │
simulateRetrieval(arch, q)          hash(q.query) < baseHitProb[arch] → "hit"
        │                            fabricated chunk headings; latency = base + hash % spread
        ▼
computeRecallAtK / Ndcg / Mrr       real arithmetic over simulated retrievals
        │
failureTaxonomy                      hardcoded per-architecture constants
        │                            (posterapp-sota: 0.0 numerical / 0.0 temporal / 0.985 anchoring)
        ▼
final-comparison.json, summary.json  → cited as SOTA results
```

At no point does any of this execute PostgreSQL, pgvector, an embedding model,
the fusion layer, the verifiers, or the adjudicator. The SOTA-vs-baseline
deltas are consequences of the `baseHitProb` table the author typed in
(`lexical-bm25`: 0.52–0.68; `posterapp-sota`: 0.97–0.99), not of measurement.
The tests in `lib/ai/eval/__tests__/competitive-benchmark.test.ts` and
`unified-eval.test.ts` then **assert the simulated outcomes**
(`recallAt10 >= 0.9`, `supportedRate === 1.0`, `recallAdvantageOverNaiveRagPct > 100`),
baking the simulator into CI — these must be rewritten against methodology
labels, not fixed values.

### 1.2 What the "0% hallucination / 0% temporal error" claims actually were

Hardcoded zeros in the `posterapp-sota` case of the failure-taxonomy `switch`
in `competitive-benchmark.ts` (`numericalErrorRate: 0.0`, comment: "100% caught
by deterministic numerical-verifier"), mirrored by
`numericalHallucinationSuppressionPct: 100` in `sotaConclusions`. No experiment
 fed these numbers. The related "claim verification AUC" figures in
`run_simulations.py` §6.3 come from Beta-distributed random scores (§3.3), not
from `claim-verifier.ts`.

## 3. `scripts/run_simulations.py` — detailed audit

Supplied 2026-09-19; committed verbatim first (`c7738e1`), then repaired
(`207bf2d`). Classification per section:

### 3.1 Statistical tests (§2–§4) — real implementations, GIGO risk

* **Bootstrap** (10,000 iterations, percentile + BCa with jackknife
  acceleration): implementation is correct; smoke-tested end-to-end.
* **McNemar** (continuity-corrected χ², exact binomial two-sided, Haldane–
  Anscombe odds ratio): correct.
* **Wilcoxon signed-rank** (Pratt zeros, tie-corrected variance, scipy p,
  effect size r = |z|/√n): correct for the **overall** comparisons.
* **Bug (fixed in `207bf2d`):** the byDomain and byLanguage `recall10` tests
  passed the **unmasked** posterapp vector (length 104) against masked baseline
  slices (length 12–48) → `ValueError` crash on every possible input. The
  script as supplied could never complete. (It fails loudly, which is the
  better failure mode — no silent wrong numbers were produced by this path.)
* **No t-test exists anywhere in the file**, despite descriptions mentioning
  one. Noted for accuracy.
* **Critical caveat:** every test is only as valid as
  `artifacts/eval/raw-query-evaluations.json`, which no committed code path
  has ever produced. Until the real-corpus benchmark writes that file from
  measured runs, these statistics describe simulation output.

### 3.2 Concurrency/queueing (§5) — simulated

Closed-loop model with **assumed** stage-time distributions (embedding
N(12, 2) ms, DB LogNormal(2.8, 0.25), reranker LogNormal(2.6, 0.25), +50 ms
think time, 4 workers, 10 DB conns, 25,000 requests/level). No measurement of
the deployed system. `littlesLawConsistent: True` was hardcoded (now computed,
and vacuously true by construction — noted in-code). **Now labelled**
`methodology: "simulated — …"` in the output JSON. Excluded from empirical
claims; see §6 for the smallest real experiment.

### 3.3 "Exact mathematical properties" (§6) — analytic/synthetic

* **RRF stability sweep:** real closed-form calculus of RRF, but computed on
  random synthetic rank matrices — a property of the RRF formula, not a
  measurement of PosterApp's fusion. Labelled analytic/synthetic.
* **DRIFT bounds:** the PPR contraction bound (α = 0.85) is real analysis, but
  `graph-drift-retrieval.ts` implements BFS frontier expansion, **not**
  personalized PageRank — the bound does not describe the shipped algorithm.
  The 5,000-run frontier simulation uses random graphs, not the production
  knowledge graph. Labelled analytic + synthetic.
* **Claim-verification PR/AUC:** scores drawn from Beta(8,2)/Beta(2,8)/Beta(3,5)
  distributions. The reported `aucRoc`/optimal-τ are properties of the
  generative model, **not** of `claim-verifier.ts`. This is the fabricated
  ancestor of the "hallucination-detection" claims. Labelled simulated with an
  explicit "NOT an evaluation of lib/ai/claim-verifier.ts" note.
* **O(V+E) vs O(N²) scaling:** analytic model with invented constants
  (256 B/node, 64 B/edge, 8 + 1.2·log₁₀N ms). Labelled analytic.

### 3.4 Hardcoded conclusion (fixed in `207bf2d`)

`summaryConclusion` asserted *"statistically significant superiority over all
6 baseline architectures … (p < 0.001 in all Wilcoxon and McNemar tests)"* and
*"effect size r > 0.85"* as **static strings**. Demonstrated during the audit
with a synthetic input where 0/12 Wilcoxon and 0/18 McNemar tests were
significant (p = 0.43, 0.22, 0.67 …): the artifact still contained the blanket
superiority claim. The conclusion is now computed from the test results and
explicitly flags non-significance. Timestamps were also hardcoded
(`2026-09-19T06:00:00.000Z`); now the actual UTC run time.

## 5. Plan to a real benchmark (Phases 0–3)

### 5.1 Phase 0 — real, annotated corpus

* Assemble 8–15 full real theses/dissertations across the five declared
  domains (CS/AI, Physics/STEM, Biomedical, Economics, General Methodology),
  SK/CS/EN mix. Sources, in priority order: (a) the repo owner's
  `workspaces/` PDFs (upload), (b) public university repositories reachable
  from this sandbox, (c) other openly-licensed dissertations the owner
  supplies. **No synthetic "theses" will be presented as real documents**; if
  any synthetic document is ever used for smoke-testing, it lives under a
  `synthetic/` prefix and is excluded from headline metrics.
* Ingest every document through the real production chunkers
  (`document-chunker.ts` / `chunker-v2.ts` → structural metadata → chunk IDs),
  with a documented PDF→Markdown path where MinerU is unavailable.
* Build `data/eval/golden-v2/` (separate from `retrieval-golden-dataset.ts`):
  chunk-ID-level relevance judgments, grades 0–3 per the rubric, produced by a
  **human annotation pass** using a small annotation script + JSON template
  under `data/eval/annotations/`, recording annotator identity and date. The
  old keyword-tag dataset is not silently conflated with the new one.

### 5.2 Phase 1 — execute every baseline for real

New `lib/ai/eval/real-corpus-benchmark.ts` (+ runner script, `pnpm eval:real`):

* **BM25/tsvector** — real `websearch_to_tsquery`/ts_rank against the ingested
  chunks on the live engine.
* **Dense MiniLM-L6-v2** — real ONNX inference (§4), indexed in pgvector,
  cosine distance queries.
* **Dense BGE-M3, Dense multilingual-E5-large** — executed only where weights
  are available; otherwise **"not executed — infrastructure unavailable"**.
  No simulated substitutes.
* **Naive RAG** — real fixed 500-token/50-overlap chunking of the same sources
  (a deliberately separate, worse chunking pass) + real top-5 vector search;
  no parent expansion, no verifiers.
* **ColBERTv2** — either a minimal *real* multi-vector MaxSim implementation
  over token embeddings from an available model, or omitted with the same
  "not executed" marker. Decision recorded here when made.
* **PosterApp pipeline** — the real `hybrid-retrieval.ts` stack end-to-end
  (fusion, parent expansion, graph leg, verifiers, adjudicator) on the live
  engine. Where the default BGE-M3 embedding is unavailable, the run uses the
  best locally-available model and **says so in the artifact** (`model` +
  `modelAvailability` fields), because a MiniLM-backed PosterApp run is a real
  measurement of a real (differently-configured) system, not of the default
  deployment.
* **Raw artifacts first:** every run persists per-query retrieved chunk IDs +
  scores + latency to `artifacts/eval/real/<architecture>-<timestamp>.json`
  **before** any aggregate is computed. Aggregates are derived files with a
  `provenance` block pointing at the raw run(s) and a `methodology:
  "empirical"` field (or an explicit `unavailable` record).

### 5.3 Phase 2 — statistics over real raw artifacts

`run_simulations.py` (fixed) consumes the real
`raw-query-evaluations.json` produced by Phase 1 (the file gains a
`methodology: "empirical"` declaration from the real runner). Its simulated
sections (§5, §6 of the script) remain available but labelled and excluded
from empirical claims.

### 5.4 Phase 3 — rewrite the reports

* Rewrite `unified-eval-runner.ts` so every section either runs something real
  or writes an explicit `{"status": "not-executed", "reason": …}` record —
  never a hardcoded number.
* Replace the (absent-from-repo) monograph's claims with a new
  `docs/benchmarks/` report generated from the real artifacts, including the
  honest failures. Rewrite the CI tests to assert on methodology labels and
  artifact structure, not on simulated values.
* Correct the inaccurate architecture descriptions wherever they appear:
  "regex/range verifier" (not AST), "deterministic rules adjudicator" (not
  Bayesian LLR), "bounded BFS graph expansion" (not MS DRIFT).

|---|---|---|
